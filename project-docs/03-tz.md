# 3. Техническое задание

## Цель и концепция
Многостраничный сайт бренда LUMORA («Твоя история. Твой мир.»): продукт превращает личные истории в персональные интерактивные приключения. Сайт объясняет продукт, показывает примеры, ведёт к заявке и привлекает трафик через блог и видео.

## Целевая аудитория
Пары, друзья, семьи; люди, которые ищут необычный подарок или совместный досуг; любители игр и интерактивных историй.

## Структура и функции
Структура: `01-structure.md`. Реализовано:

| Функция | Реализация |
|---|---|
| Многостраничность, навигация, бургер-меню | `build.mjs` + `src/lib/layout.mjs` |
| Каталог: поиск, фильтр по жанру, сортировка | `main.js`, данные `adventures.mjs` |
| Страницы приключений, статей, видео | генерируются из данных |
| Блог: поиск, категории, теги | `main.js`, `articles.mjs` |
| Видео: плеер загружается по клику | `main.js` |
| FAQ (с разметкой FAQPage) | `faq.mjs` |
| Форма заявки: валидация, защита от повторной отправки, индикатор, сообщения, honeypot, согласие | `main.js` |
| Cookie-баннер и отложенная загрузка Метрики | `main.js` |
| SEO: title/description/canonical/OG/JSON-LD/sitemap/robots | `layout.mjs`, `build.mjs` |
| 404, noindex для служебной страницы | `static.mjs` |

## Технический стек и обоснование
HTML, CSS, JS без фреймворков + Node-скрипт сборки без зависимостей. **Обоснование:** публикация на GitHub Pages допускает только статику. Next.js, PostgreSQL, Prisma и CMS из исходного промпта потребовали бы сервера и не работают на Pages.

**Что из исходного промпта не реализуется на этом этапе и почему:**

| Пункт | Статус | Решение |
|---|---|---|
| БД, ORM, миграции, сущности User/Order и т. д. | не реализовано | нет сервера |
| Админ-панель, роли, авторизация | не реализовано | контент в файлах данных; опция: подключить headless-CMS (Decap CMS работает со статикой) |
| Сохранение заявок в БД | заменено | внешний приёмник форм (`FORM_ENDPOINT`) |
| Оплата, заказы, вебхуки | не реализовано | платёжный провайдер не выбран; страница `/buy` честно говорит, что оплаты нет |
| Email-уведомления | через приёмник форм | настраивается в его кабинете |
| Загрузка файлов, объектное хранилище | не реализовано | видео — внешним хостингом, графика — SVG |
| Rate limiting, CSRF | не применимо | серверной части нет; защита — honeypot и ограничения приёмника форм |

**Этап 2 (при росте):** VPS или Vercel + PostgreSQL, перенос на Next.js, CMS, серверные заявки, оплата.

## Дизайн-требования
Палитра: фон `#080D18`, вторичный `#0B1423`, карточки `#171D2A`, текст `#F5F5F7`/`#B7B8C1`, золото `#D8AA60`/`#F5D49B`, границы `rgba(255,255,255,.14)`. Шрифт Inter. Композиция главной по референсу: стеклянная панель навигации, крупный заголовок слева, золотая и контурная кнопки, светящаяся дверь справа (SVG), индикатор прокрутки. Компоненты: Header, Footer, Button, SectionHeading, GameCard, ArticleCard, VideoCard, Breadcrumbs, Search, FilterChips, Accordion, Field, VideoPlayer, CookieConsent, EmptyState (`src/lib/components.mjs`, `main.css`).

Не реализованы как отдельные компоненты: Modal, Pagination (6 приключений и 4 статьи не требуют), LoadingState/ErrorState (есть статусы форм).

## Требования к контенту
Демо-приключения помечены как демонстрационные. Нет выдуманных отзывов, статистики, цен, платформ. Видео пока «скоро». Перед запуском: проверить статьи на уникальность внешним сервисом, юристу проверить `/privacy`, `/terms`.

## SEO
См. `05-seo.md`.

## Безопасность
Нет серверной части и хранилища персональных данных на сайте. Контент статей — доверенный HTML из репозитория. В JSON-LD экранируется `<`. Секреты в код не попадают: в сборку подставляются только публичные значения (счётчик Метрики, URL приёмника форм). Внешние ссылки открываются с `rel="noopener"`.

## Производительность
Нулевые зависимости; графика — SVG (вес минимален); шрифт с `display=swap`; видео не грузится до клика; скрипт `defer`. Измерения Lighthouse не проводились: выполните после публикации.

## Критерии приёмки
1. `npm run check` без ошибок (ссылки, title, H1, canonical, дубли).
2. Все страницы открываются, навигация работает на 320 px и на десктопе.
3. Форма: валидация, три состояния ответа (успех/ошибка/нет endpoint).
4. `sitemap.xml`, `robots.txt` доступны после публикации.
5. Визуальное соответствие референсу.
